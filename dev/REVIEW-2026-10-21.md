4. Security
-----------

- `RStudio/launch_rserver.sh:17`: the default password is the first 16 hex
  digits of `md5(date -R)`.  `date -R` has one-second resolution, and the job
  start time is visible to other users through `squeue`, so the candidates can
  be enumerated.  Fix: `openssl rand -hex 16`, as the generated
  `RStudio_server` wrapper already does for its keys (`RStudio/README.md:159–165`).
- `Other/cellxgene-vip:16–17, 52`: the server listens on the node's network
  name without authentication and the script prints no warning.
  `Other/launch_jbrowse2` has the same exposure but warns (lines 7–10, 149).
- `RStudio/launch_rserver.sh:9`: the script runs under `/bin/sh`, which is
  dash in the Debian image; dash does not run an `EXIT` trap when killed by
  SIGTERM (tested with dash outside the image), so a Slurm cancellation leaves
  `RSTUDIO_TEMP` behind.  The README already tells users to clean it.
  Trapping `INT TERM` as well would cover that case.


5. Issue #9 (autogenerated `stacks` modules)
--------------------------------------------

The cause is visible in `mkDebMedModule.sh`: line 16 selects package files
with `grep /bin/`, which also matches `/usr/lib/<package>/bin/`; line 28 keeps
only the basename; line 32 runs `singularity exec … $prog`, which fails when
the program is not on the image's `PATH`.  Running the full path from
`$PROGLIST` would fix it, as the issue suggests.

`mkDebMedModule.sh` has not been referenced since 2025-09-04
(“Prepare Trixie Debian Med modules”), when generation moved to `debalamod`.
If `debalamod` fixes the problem, the issue can be closed and the script
deleted; otherwise the fix belongs in `debalamod`.
